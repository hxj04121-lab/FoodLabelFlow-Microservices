## Proposed decision

1. **Locations and Published Language.** Compliance OpenAPI and its wire primitives live under `contracts/openapi/compliance*`; ImpactFinding event and shared HTTP/event payload under `contracts/events/impact-finding*`. Test/capacity documents use `docs/swe5001/test-plan-G0-M2*`. Existing baseline runtime/contracts remain unchanged.
2. **Stable error/ID interface.** Reuse the baseline ApiError wire fields `{code,message,traceId,evidenceId}` as one schema referenced by all M2 failures. IDs remain opaque strings, eventId UUID, timestamps RFC3339 UTC, version/revision numbers positive. Propagate actual correlation via required `X-Correlation-ID` headers and event correlationId. traceId/evidenceId must correspond to real records/identifiers; no internal failure details or fabricated evidence.
3. **Exact validation and bounded replay.** Request carries labelVersionId, versionNumber, draftRevision, declarations, formulaVersionId, jurisdiction, ruleSetVersionId and organisationId matching JWT org_id. The tenant-scoped key is `labelVersionId:draftRevision`, bound to the whole canonical snapshot. Same key/snapshot returns the persisted run (200 replay, 201 first completion); changed snapshot conflicts (409). The caller forwards the actor JWT, times out at 2 s, retries at most once with the same key, and cannot submit without an exact local PASSED record. Key encoding, draftRevision and replay status details require M4 agreement; they refine FINAL §6.2 rather than alter service boundaries.
4. **Two-phase evidence.** POTENTIAL evaluates the current released formula with candidate specification substituted. CONFIRMED uses the released adopted formula. Payload preserves required, declared, missing and unresolved component evidence plus immutable specification/formula/label/rule-set references. `missing = required - declared`; unresolved forces REVIEW_REQUIRED. Only CONFIRMED + REVIEW_REQUIRED creates a label task. Missing exact projections fail closed; no source-table reads or latest-version substitution.
5. **Canonical event-envelope handoff.** M1 supplied `contracts/events/event-envelope.v1.schema.json` in PR8 at `a788fa5fc815c34cb23cf219d5194d92a51937bb`. Its actual candidate passes M2 conformance for all examples, ten required-field negatives and UUID/UTC/version negatives. The M2 companion adoption composes this shared `$ref`, removes the duplicate local EnvelopeInterface and preserves the event type, producer and payload constraints. PR2–5 retain their self-contained interface until the M1 artifact is integrated; a missing artifact still blocks conformance. Both owners' checks and reviewer/owner decisions are required before freeze. M4 LabelPublished/Label Workflow artifacts remain outstanding.
6. **Measurement plan.** Preserve all October 1 numeric targets: 3-replica sustainable rate ≥2× one replica at p95 ≤2 s/errors <1%; failover at ~50% R3 with error-window ≤10 s, recovery ≤60 s and replacement Ready <180 s. Use fixed replica CPU/memory and an open arrival-rate workload over local immutable projections. Record protective gateway limits per instance (not global exact quotas); no claimed runtime result or resource provisioning follows from this plan.

## Consequences and acceptance

The actual M2 schemas and examples are locally testable while the shared artifact is pending. Local success cannot establish all-v1 interoperability or task Done. M1 must agree to the event envelope and consistent error/ID conventions; M4 must accept validation/impact wire details and measurement definitions. Remaining peer target contracts must pass steward review. Publication uses one draft PR per subtask in the order STCN-27, STCN-26, STCN-28 and STCN-29. Dependent PRs are stacked for focused review and must target main after prerequisites merge. CI, human approval and merged evidence remain required. This ADR becomes accepted only with recorded reviewer/owner decisions; freezing v1 or changing an approved contract requires corresponding ADR/source/contract updates.
