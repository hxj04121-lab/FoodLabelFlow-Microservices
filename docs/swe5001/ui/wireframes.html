Read-only, permission and conflict states

Released versions have no edit action. Hide write actions for other organisations and read-only roles. A 403 explains the denied action; a 409 preserves input and requires reloading the version before trying again. Publication failure must not display success.

Empty, unresolved and unavailable states

Empty: no findings returned for the current filters; this is not proof of NO_ACTION. Page with the server’s opaque nextCursor.

UNRESOLVED: show the raw phrase, component, specification and UNMAPPED/AMBIGUOUS reason. REVIEW_REQUIRED remains in force even when missing is empty.

422 / loading: exact projections are not ready; explain the wait and offer refresh. Never replace unavailable declarations with an empty set.

Available candidate contract: GET /api/compliance/impact-findings and /{findingId}. Labels and names need owner API hydration. Filters: kind/outcome; a production filter changes the server query.
