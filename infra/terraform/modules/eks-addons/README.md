# EKS foundations

This module reuses the existing EKS cluster, VPC, OIDC provider, node groups, and autoscaler role. It installs missing EBS CSI, Load Balancer Controller, Cluster Autoscaler, metrics-server, workload namespaces, and NetworkPolicies. It creates no VPC, EKS cluster, static ALB, listener, or application workload.

The root retains its existing ALB and target group. The Gateway service chart can render a TargetGroupBinding for that existing target group, after LBC and its CRD are Ready. HTTPS remains a separately reviewed listener/certificate/DNS change. Do not use a controller-owned Ingress to create a duplicate edge.

`manage_vpc_cni=false` is the default. This preserves the healthy self-managed CNI and node-role fallback permission. Strict NetworkPolicy enforcement must still be verified and, when disabled, enabled through an approved parameter patch after the policy-endpoint CRD and traffic policies are present. Set `manage_vpc_cni=true` only for an explicitly reviewed managed-add-on migration; that path overwrites self-managed fields and must not be used as an implicit reinstall.

IRSA roles restrict trust to exact ServiceAccount subjects. EBS CSI uses the AWS driver policy. LBC's TargetGroupBinding-only policy can describe resources, modify target-group settings, and register/deregister targets on the existing Gateway and Keycloak groups plus only the fixed-name frontend group. The frontend group ID is not known until that group is provisioned; the ARN pattern is limited to `foodlabelflow-staging-frontend/*` and should be replaced with the exact ARN after creation. It has no EC2 security-group write actions and cannot create or modify an ALB, listener, subnet, or security-group rule. A read-only check verifies that the existing ALB/backend security groups and NetworkPolicies already permit TCP/8080, so this mode does not depend on controller-managed security-group changes. EBS CSI creation rejects ownership conflicts. AWS resolves driver compatibility against the cluster minor version; the exact selected version must be recorded in the approved plan. Helm controller charts are pinned, autoscaler overrides the chart image to the cluster minor, and controller requests/replicas are declared for capacity planning.

The GitHub deploy Access Entry maps to `spectrace-staging-deploy`. The three namespace Roles grant the group only the Gateway, Frontend, and Keycloak custom resources needed by the protected workflows; reads/patches are restricted to the named existing TargetGroupBindings and Keycloak CR. This complements, but does not widen, namespace-scoped `AmazonEKSEditPolicy`, which does not authorize these custom API groups.

The encrypted gp3 StorageClass uses `WaitForFirstConsumer` for AZ placement and `Delete` reclaim semantics. Existing namespace/StorageClass ownership must be inspected and adopted through separately approved state operations when needed. Never delete existing PVC data during installation or rollback.

Install traffic policies before enabling strict enforcement. Verify all controller webhooks and APIService backends, DNS, kubelet, messaging peer ports, database access, and actual workload labels before narrowing existing rules.

Run `scripts/check_eks_addons.sh` and the mocked Terraform safety tests offline. Run `scripts/verify_eks_addons.sh foundations` on the authorized VPC path, then `deploy` with `STCN_ACM_CERTIFICATE_ARN`, `STCN_ALB_ARN`, `STCN_ALB_TARGET_GROUP_ARN` (Gateway), `STCN_KEYCLOAK_TARGET_GROUP_ARN`, and `STCN_VPC_ID`. Deploy mode verifies the HTTPS path rules, both target groups and health checks, ENI/ALB/backend security-group rules, and ALB subnet NetworkPolicy ingress. It is read-only. Static tests, Ready core pods, and a saved plan are separate from live storage, policy, ingress, and application acceptance.
