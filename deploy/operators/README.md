# Staging operators

`scripts/staging.sh up` installs pinned cert-manager, RabbitMQ Cluster and Topology Operators, and the Keycloak Operator using the upstream release manifests and the Keycloak Kustomize overlay. Apply steps are repeatable. Apply the RabbitMQ cluster with `kubectl apply -f deploy/operators/rabbitmq/rabbitmq-cluster.yaml`, then install topology with `helm upgrade --install spectrace-topology deploy/helm/rabbitmq-topology -n rabbitmq`.

The Keycloak realm and org/role/client claims remain owned by G1-M4 (`deploy/keycloak`). After the RDS endpoint and runtime credentials are available, render `deploy/operators/keycloak/keycloak.yaml.tmpl` with `RDS_ENDPOINT`, create the `keycloak-db` Secret from the protected staging environment, and apply the Keycloak custom resource. Do not commit rendered output or Secret data.

RabbitMQ cluster operator v2.22.3 and topology operator v1.20.2 are pinned. The topology CRs follow architecture v3 §6.3–6.4; `helm template` is used for offline review before apply. User credentials are generated by the topology operator into service namespaces. Operators and workloads require CRDs/webhooks to be ready before applying their custom resources.
